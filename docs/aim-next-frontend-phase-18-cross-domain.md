# AAS–AIM Future Frontend — Phase 18, Cross-Domain Integration (Tranche 1)

**Baseline:** Frozen 190 active functions / 15 domains / 78 screen targets. **Status:** Frontend code delivered; operational source integrations are not connected.

## Delivered

- Implemented `SCR-HOM-003` Universal Search as a scope-bound GOV-012 frontend, replacing its Phase 17 placeholder.
- Added atomic validation for upstream-authorized search projections, bounded to 10,000 records and an explicit `navigationScopeKey`.
- Added case-insensitive search and domain/state/asset filtering, paging, provenance inspector, canonical owning-screen routing, and seven distinguishable data states.
- Added a persistent selected-asset **navigation** context in the app shell, populated only from a validated AIR snapshot when a trusted navigation scope is present.
- Wired AIR register/hierarchy/relationship selections into the shell context; shell selection persists across domains and is shown in Universal Search.
- Used a scope-keyed React app boundary: changing `navigationScopeKey` immediately remounts all shell state rather than leaking previous selections or search filter state.
- Added permanent model regression tests, React component tests, and app-composition tests.

## Integration boundary

`FutureAimApp` accepts:

```tsx
<FutureAimApp
  navigationScopeKey={trustedScopeRevision}
  assetSnapshot={authorizedAssetSnapshot}
  assetScopeKey={trustedScopeRevision}
  discoverySnapshot={authorizedSearchProjection}
/>
```

`trustedScopeRevision` must be generated by the trusted upstream application/session orchestration layer and change when principal, tenant, site, or effective data authorization changes. The client **cannot verify** the identity or authorization from that key. Search projection format is:

```ts
{
  scopeKey: trustedScopeRevision,
  records: [{
    id: "opaque-record-id", objectRef: "...", objectType: "RBIAssessment",
    title: "...", domain: "RBI", screenId: "SCR-RBI-002",
    state: "APPROVED", sourceRef: "...", revision: "...",
    assetId: "authorized-asset-id", occurredAt: "2026-10-01T00:00:00Z"
  }]
}
```

This is **an example of the data contract only**, not source data supplied at runtime. Do not use `discoveryFixture()` outside tests. The backend must authorize every search result (including titles, IDs, counts and source references) **before** returning it. Do not derive a privileged search index from arbitrary browser-visible snapshots.

Asset selection is **not a scope grant**, does not filter backend requests, and does not automatically focus records in other domain workspaces. The selected asset is exposed to Search as a local optional filter and is available for future domain integration. Opening a search result routes to the owning screen, not to an automatically authenticated record or approval action. If a selected asset disappears from the authorized AIR dataset, it is hidden; a new trusted scope must rotate the navigation key.

## Validation & testing

- Permanent discovery model tests cover malformed source records, invalid IDs, cross-domain screen mismatch, invalid timestamp, scope mismatch, duplicates, all-or-nothing rejection, immutable cloning and combined filters.
- React/jsdom tests cover disconnected/error states, search filtering, selection, canonical navigation and asset-context interaction.
- App integration tests cover screen access, cross-domain navigation and scope rotation.
- Isolated strict TypeScript checking and direct model test runner are available; **official Vitest/jsdom and production Vite build must be run using pinned Node/pnpm before release**.

## Deliberate exclusions and next tranche

- No networked search, SSO, tenant authorization, data synchronization, or local persisted navigation state.
- No content upload, document preview or evidence retrieval. The search inspector shows references only.
- No authoritative record selection in target domain workspaces, generic domain mutation, or approval action.
- Next tranche: reusable authorized Evidence/Revision viewers, exact cross-domain object-to-object routing, shared loading/error/empty states, accessibility audit and official React suite execution.
